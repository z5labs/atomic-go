# Talking to the API

The Atomic API is one gRPC contract, package `atomic`, served by the `atomicd` daemon and called in-process by the Atomic CLI. libatomic owns two halves of it: the protobuf contract with its code generation, and the handlers that implement the methods ([`lib.rs#L1-L20`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/lib.rs#L1-L20)). It does not own the transport. The socket bind, the single-instance lock, the tonic `Server` wiring and the `atomicd` binary live in a separate shell ([`lib.rs#L22-L24`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/lib.rs#L22-L24)). This page separates what libatomic specifies from what it leaves to that shell. Gaps are listed under [Open questions](#open-questions).

## What libatomic specifies

| Concern | Specified in libatomic? | Where |
|---|---|---|
| Message and service definitions | Yes, the `.proto` files under `proto/atomic/` | [`README.md#L6-L9`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/README.md?plain=1#L6-L9) |
| Method path form and encoding | Yes, by the generated tonic/prost code | [Framing and encoding](#framing-and-encoding) |
| Contract version and its header | Declared; not enforced by any handler | [Version negotiation](#version-negotiation) |
| Connection handshake | No connection-level handshake; the contract's only handshake is the `GetCapabilities` call | [Handshake](#handshake) |

| Socket path, listener, TLS, iroh | No | [`lib.rs#L22-L24`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/lib.rs#L22-L24) |
| In-process byte boundary | Yes, `LocalService` and the Node addon | [In-process LocalService](#in-process-localservice) |

## Transports

The contract is meant to be served unchanged over a Unix-domain socket, a named pipe, TLS or iroh, to both a local daemon and a hosted server; there is no second protocol ([`README.md#L3-L4`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/README.md?plain=1#L3-L4)). In libatomic's own words, the `atomicd` shell serves the handlers over a private Unix-domain socket, and the CLI's local mode calls the same handlers in-process ([`mod.rs#L1-L7`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/mod.rs#L1-L7)). A local client that cannot reach the daemon may start or restart it and retry, but may never open the repository database itself ([`daemon_messages.proto#L14-L17`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/daemon/daemon_messages.proto#L14-L17); [`common.proto#L33-L34`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/common/common.proto#L33-L34)).

The Unix-socket client in the example connects with a tonic `Endpoint` for `http://localhost`, replacing the connector with one that opens the socket, so the URI authority is not meaningful ([`agent_sandbox_bench.rs#L435-L445`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/examples/agent_sandbox_bench.rs#L435-L445)). It raises the client's decode limit to 64 MiB ([`agent_sandbox_bench.rs#L446`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/examples/agent_sandbox_bench.rs#L446)), the same value `GetCapabilities` advertises as `max_message_bytes` ([`services.rs#L226-L227`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L226-L227)).

`identity_transport.rs` and `signer_refresh.rs` are not part of the client-facing transport. They are the daemon's and CLI's outbound calls to remote storage servers, for project-identity binding and signer-key discovery ([`identity_transport.rs#L1-L8`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/identity_transport.rs#L1-L8); [`signer_refresh.rs#L1-L21`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/signer_refresh.rs#L1-L21)).

## Framing and encoding

**Code generation.** `build.rs` collects every `.proto` file under `proto/`, compiles them with protox (a pure-Rust replacement for `protoc`) using `proto/` as the include root, and generates both tonic client and tonic server code from the result ([`build.rs#L22-L35`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/build.rs#L22-L35), [`build.rs#L42-L45`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/build.rs#L42-L45)). No codec, compression or message-size option is configured there. The generated module is included as `libatomic::atomic`, also exported as `libatomic::proto` ([`lib.rs#L26-L34`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/lib.rs#L26-L34)). tonic-generated services speak standard gRPC over HTTP/2 with protobuf-encoded messages, so a conforming gRPC client in another language can call them using stubs generated from the same `.proto` files.

**Method paths.** Every file declares `package atomic` ([`common.proto#L38`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/common/common.proto#L38); [`daemon_service.proto#L7`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/daemon/daemon_service.proto#L7)), so a method's gRPC path is `/atomic.<Service>/<Method>`, for example `/atomic.DaemonService/ResolveRepository` and `/atomic.RepositoryQueryService/Status` ([`local.rs#L65-L66`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L65-L66), [`local.rs#L92`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L92), [`local.rs#L111`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L111)). Imports are written relative to `proto/`, as in `atomic/common/common.proto` ([`README.md#L57`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/README.md?plain=1#L57)).

**Messages.** Requests and responses are ordinary proto3 messages. Handlers distinguish absent `optional` fields from zero values; for example, inside a present `StatusOptions`, each unset optional field takes its domain default rather than `false` ([`convert.rs#L61-L65`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/convert.rs#L61-L65)). Every repository-scoped request carries `RepositoryRef repository = 1`, and every ordinary mutation carries `RequestMeta` and returns `ResponseMeta` at field 100 ([`README.md#L77-L87`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/README.md?plain=1#L77-L87)). Retired field numbers are reserved, not reused ([`README.md#L43-L45`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/README.md?plain=1#L43-L45)).

Each stream's message order and termination is described on its method page. For `Materialize`, entry frames come first and a final summary frame closes the logical stream ([`sandbox_service.proto#L84-L87`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/sandbox/sandbox_service.proto#L84-L87)); the example client reads frames until the summary and treats an end of stream before it as an error ([`agent_sandbox_bench.rs#L489-L516`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/examples/agent_sandbox_bench.rs#L489-L516)). The in-process `LocalService` cannot carry streams: `call` returns a single byte buffer ([`local.rs#L90`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L90)).

## Descriptor set

libatomic embeds the compiled contract as `FILE_DESCRIPTOR_SET`, the bytes of a protobuf `FileDescriptorSet` built from the canonical `proto/` tree. Bindings can generate their types from it without `protoc` or a source checkout ([`lib.rs#L46-L50`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/lib.rs#L46-L50)). `build.rs` writes it from the same protox compilation that feeds code generation ([`build.rs#L36-L39`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/build.rs#L36-L39)). A test decodes it as a `FileDescriptorSet` and finds `RepositoryQueryService.Status` in it ([`local_service_test.rs#L617-L630`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/local_service_test.rs#L617-L630)). The Node addon returns the same bytes from `descriptor()` ([`node.rs#L27-L30`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/node.rs#L27-L30)).

The descriptor describes the full contract. It does not mean every method has a handler, or that `LocalService` routes it ([`README.md#L83-L86`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/README.md?plain=1#L83-L86)). Because the [method options](types.md#method-options) are extensions of `MethodOptions` ([`options.proto#L57-L70`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/common/options.proto#L57-L70)), they are part of the descriptor; `check_contract.py` reads them from a compiled descriptor set in the same way ([`check_contract.py#L105-L111`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/check_contract.py#L105-L111)).

At this commit the service protos declare 105 rpcs across 15 services. libatomic's own documents give older counts: 94 in `proto/README.md` and `COVERAGE.md`, and 97 in the crate documentation ([`README.md#L43`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/README.md?plain=1#L43); [`COVERAGE.md#L26`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/COVERAGE.md?plain=1#L26); [`lib.rs#L7-L8`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/lib.rs#L7-L8)).

## Version negotiation

The contract revision is 2. `ContractVersion` holds the constant, and revision 1's draft behaviour is retired ([`common.proto#L42-L48`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/common/common.proto#L42-L48)). `GetCapabilities.protocol_version` is the negotiated value, and a mismatch "fails hard" in both directions ([`daemon_messages.proto#L86-L88`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/daemon/daemon_messages.proto#L86-L88)). Older draft clients must fail negotiation rather than send fields that a new server would ignore ([`README.md#L43-L45`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/README.md?plain=1#L43-L45)).

`CONTRACT.md` sets the obligations: every call other than the negotiation pair must carry the gRPC metadata entry `x-atomic-contract-version: 2`, and a missing or mismatched version fails before dispatch ([`CONTRACT.md#L34-L38`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L34-L38)). The negotiation pair, `DaemonService.Health` and `DaemonService.GetCapabilities`, needs no capability, because a client must discover the endpoint first ([`options.proto#L60-L65`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/common/options.proto#L60-L65)).

What libatomic does:

- `GetCapabilities` returns `protocol_version: 2` ([`services.rs#L216-L217`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L216-L217)).
- No libatomic handler reads `x-atomic-contract-version`; the metadata checks in the handlers look only at credentials ([`sandbox_grants.rs#L583-L588`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L583-L588); [`compact.rs#L25-L28`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact.rs#L25-L28)). Enforcing the header is left to the serving shell ([`lib.rs#L22-L24`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/lib.rs#L22-L24)).
- `ERROR_CODE_PROTOCOL_VERSION_MISMATCH` exists and maps to gRPC `INTERNAL` ([`error.proto#L30`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/common/error.proto#L30); [`state.rs#L443`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L443)), but nothing in libatomic produces it.

A client should therefore:

1. Call [GetCapabilities](services/daemon.md#getcapabilities) (no version header is required for it) and refuse to continue unless `protocol_version` is 2.
2. Send `x-atomic-contract-version: 2` on every other call. libatomic's handlers ignore it, but the contract requires it of the transport.
3. Gate optional request fields on the returned feature tokens. [Health](services/daemon.md#health) returns a shorter list of quick-gate tokens ([`daemon_service.proto#L13-L15`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/daemon/daemon_service.proto#L13-L15)). The method matrix in `GetCapabilities` is not reliable at this commit; see [GetCapabilities](services/daemon.md#getcapabilities).

### Handshake

libatomic defines no connection-level handshake of its own; connection setup belongs to the serving shell, which is not in libatomic ([`lib.rs#L22-L24`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/lib.rs#L22-L24)). The contract calls `GetCapabilities` "the capability handshake": it returns versions, endpoint kind, method matrix, limits and auth requirements, and needs no capability ([`daemon_service.proto#L24-L25`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/daemon/daemon_service.proto#L24-L25)). The limits it returns are negotiated values that the daemon may lower per principal ([`daemon_messages.proto#L38-L41`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/daemon/daemon_messages.proto#L38-L41)), and the contract says to negotiate limits before allocating opaque payloads ([`CONTRACT.md#L71`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L71)). The daemon state holds the repository registry, the shutdown notifier, a log path and the grant store, and no per-client session ([`state.rs#L284-L289`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L284-L289)), so no handler can tell whether a client called `GetCapabilities` first; the steps above are the client's own discipline.

## Authentication and authorization

**The contract.** Four independent declarations govern each method: execution scope, allowed callers, required capabilities and effects ([`CONTRACT.md#L13-L24`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L13-L24)); see [method options](types.md#method-options). Caller class is established by middleware, never asserted by a request body, and socket access alone is not authorization ([`options.proto#L33-L35`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/common/options.proto#L33-L35)). The local transport authenticates an operating-system principal, TCP authenticates over TLS, and iroh authenticates its encrypted peer connection ([`CONTRACT.md#L39-L42`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L39-L42)). Credentials travel in gRPC metadata ([`CONTRACT.md#L43-L47`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L43-L47)):

| Caller | Credential | Metadata key |
|---|---|---|
| Sandbox | Sandbox token, on every sandbox call, including the Provenance, Vault, Knowledge and Attestation services | `x-atomic-sandbox-token-bin` (binary metadata) |
| Other remote identity | Bearer token with a verified audience | `authorization: Bearer ...` |

Multiple or conflicting credentials are refused, a restricted token is never reclassified as an unrestricted identity, and tokens in request bodies are retired ([`CONTRACT.md#L46-L47`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L46-L47)). Credentials, the method allowlist, the resource grant and expiry are checked before a repository is opened or replay state is consulted ([`CONTRACT.md#L48-L51`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L48-L51)).

**What libatomic does.** libatomic carries no transport; the host process serving the handlers decides how a caller is authenticated ([`sandbox_grants.rs#L9-L11`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L9-L11)). A handler sees a sandbox principal in one of two ways: the host attached a verified grant to the request's extensions, or the request carries `x-atomic-sandbox-token-bin`, which libatomic resolves against its grant store. A request with neither is treated as a local, trusted caller ([`sandbox_grants.rs#L11-L20`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L11-L20)). The consequences for a client:

- A request with more than one sandbox token, or a token together with an `authorization` entry, fails with `ERROR_CODE_UNAUTHORIZED`; so does malformed token metadata ([`sandbox_grants.rs#L583-L596`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L583-L596)). An unknown, revoked or expired token fails with `ERROR_CODE_UNAUTHORIZED`, and a request for a view with no live token with `ERROR_CODE_SANDBOX_TOKEN` ([`sandbox_grants.rs#L211-L221`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L211-L221)).
- Local-only handlers that check refuse a sandbox caller with `ERROR_CODE_FORBIDDEN` ([`sandbox_grants.rs#L607-L617`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L607-L617)), and a sandbox call needing a capability its grant lacks fails with `ERROR_CODE_FORBIDDEN` ([`sandbox_grants.rs#L495-L504`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L495-L504)).
- The host must route methods outside the sandbox allowlist away from sandbox principals before dispatch ([`sandbox_grants.rs#L64-L69`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L64-L69)). libatomic narrows this further: only the methods in `SANDBOX_SCOPED_METHODS` (the negotiation pair, the six SandboxService data operations and the eight provenance turn and checkpoint rpcs) enforce the grant's scope in their handlers. The Vault, Knowledge and Attestation methods and the provenance session reads are on the allowlist but not scoped, and a host should refuse sandbox principals on everything outside the scoped list ([`sandbox_grants.rs#L105-L127`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L105-L127)). See [Callers, grants and tokens](services/sandbox.md#callers-grants-and-tokens).
- No libatomic handler validates an `authorization` bearer token. Handlers only check whether one is present, to refuse mixed credentials or, in compaction, any credential at all ([`sandbox_grants.rs#L588`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L588); [`compact.rs#L22-L33`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact.rs#L22-L33)).
- For non-sandbox callers, libatomic does not check `required_capability` or `allowed_caller`. The compaction handler says the serving transport must enforce `LOCAL` and `maintenance.admin` before calling it ([`compact.rs#L22-L24`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact.rs#L22-L24)).

Sandbox grants are minted by `SandboxService.OpenSandbox`, a local-only method ([`sandbox_service.proto#L13-L21`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/sandbox/sandbox_service.proto#L13-L21)). They last between 1 second and 365 days, two hours by default ([`sandbox_grants.rs#L41-L47`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L41-L47)), and the default grant store keeps only token hashes in memory, so a restart invalidates every token ([`sandbox_grants.rs#L22-L25`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L22-L25)). See [OpenSandbox](services/sandbox.md#opensandbox).

`GetCapabilities` advertises `tls_required: false`, `audience_binding: false`, identity scheme `did:atomic` and credential scheme `local-socket-uid` ([`services.rs#L235-L240`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L235-L240)). The proto comment says the TLS requirement applies to TCP, and iroh provides its own authenticated transport ([`daemon_messages.proto#L60-L61`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/daemon/daemon_messages.proto#L60-L61)).

## Repository resolution

Remote clients never send filesystem paths; local path discovery resolves to a persistent repository ID before the first repository request ([`common.proto#L23-L26`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/common/common.proto#L23-L26)). The usual sequence for a local client is:

1. Call [ResolveRepository](services/daemon.md#resolverepository) with the working-copy path. It returns a [RepositoryRef](types.md#repositoryref) and the workspace's root, relative directory and current view ([`daemon_messages.proto#L105-L122`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/daemon/daemon_messages.proto#L105-L122)).
2. Pass that `RepositoryRef` as field 1 of every repository-scoped request ([`README.md#L77-L83`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/README.md?plain=1#L77-L83)).

The `LocalService` documentation shows the same two steps ([`local.rs#L74-L87`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L74-L87)).

A `RepositoryRef` is only valid on the daemon state that registered it. The registry lives in memory ([`state.rs#L284-L299`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L284-L299)), and a request naming an unregistered ID fails with `ERROR_CODE_REPOSITORY_NOT_FOUND` and the hint "resolve it by path first", with no filesystem fallback ([`state.rs#L329-L348`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L329-L348)). A reference from one `LocalService` is refused by another with gRPC `NOT_FOUND` ([`local_service_test.rs#L113-L130`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/local_service_test.rs#L113-L130)). The ID itself is a digest of the canonical root path ([`state.rs#L66-L75`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L66-L75)), so it is the same after a daemon restart, but the restarted daemon accepts it only after the path is resolved again. A client that gets `REPOSITORY_NOT_FOUND` for a reference that worked before should resolve the path again.

## Request metadata and idempotency

The contract makes every mutation idempotent through [RequestMeta](types.md#requestmeta): the caller sends a UUID v4 `request_id` and its own `observed_at`; the server echoes the ID in [ResponseMeta](types.md#responsemeta) (field 100), returns the original outcome for a replay, and fails a reused ID with different contents with `ERROR_CODE_IDEMPOTENCY_MISMATCH` ([`common.proto#L8-L22`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/common/common.proto#L8-L22); [`CONTRACT.md#L54-L59`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L54-L59)). After a durable commit, a lost response is meant to be recovered by replay, not by repeating effects ([`CONTRACT.md#L68-L71`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L68-L71)).

libatomic does not implement replay at this commit:

- Handlers echo `request_id` into `ResponseMeta` when the request carried `RequestMeta`, and return no `ResponseMeta` when it did not ([`services_agent.rs#L1233-L1239`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L1233-L1239)). Some handlers echo an empty ID instead when `RequestMeta` is absent ([`services.rs#L282`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L282), [`services.rs#L289-L296`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L289-L296)).
- Every `ResponseMeta` they build has `replayed: false` ([`services_agent.rs#L1236-L1237`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L1236-L1237); [`services.rs#L294-L295`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L294-L295)). Only `SubmitChange` sets `snapshot`, after an accepted submission ([`services_sandbox.rs#L839-L843`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L839-L843)); see [ResponseMeta](types.md#responsemeta).
- Nothing produces `ERROR_CODE_IDEMPOTENCY_MISMATCH`, and only `CompactDatabase` validates that `request_id` is a UUID ([`compact.rs#L35-L44`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact.rs#L35-L44)).

A client should still send a fresh UUID v4 per logical mutation, because the contract requires it, but must not assume that resending a mutation after a lost response is safe. Treat a retried mutation as a second request.

`observed_at` is the caller's clock; the server must not substitute its own ([`common.proto#L18-L22`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/common/common.proto#L18-L22)). The provenance handlers read it as whole seconds and use 0 when it is absent ([`services_provenance.rs#L155-L163`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_provenance.rs#L155-L163)).

## In-process LocalService

`LocalService` is an in-process API for trusted local applications. It builds no client channel, listener or service process ([`local.rs#L1-L2`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L1-L2)), and it is not a substitute for remote authentication middleware ([`local.rs#L35-L46`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L35-L46); [`CONTRACT.md#L121-L122`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L121-L122)). It is a Rust API; the only other binding libatomic ships is the Node addon below. libatomic defines no stable C ABI for other languages ([`README.md#L151-L153`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/README.md?plain=1#L151-L153)).

**Calling convention.** `call(method, request)` takes a canonical gRPC method path and the protobuf encoding of the request message, and returns the protobuf encoding of the response message or a tonic `Status` ([`local.rs#L65-L66`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L65-L66), [`local.rs#L90`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L90)). There is no gRPC length-prefix framing and no metadata: each call decodes the bytes, builds a fresh `tonic::Request` around the message, and calls the existing handler ([`local.rs#L111-L122`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L111-L122), [`local.rs#L442-L444`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L442-L444)). Because the request has no metadata, it carries no version header or credentials, and the handlers treat it as a local, trusted caller ([`sandbox_grants.rs#L19-L20`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L19-L20)).

**Instances.** Keep one instance per application and reuse it or its clones; clones share repository routing and serialization gates, not open database handles ([`local.rs#L35-L38`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L35-L38)). A repository reference belongs to the instance that resolved it and its clones ([`README.md#L52-L53`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/README.md?plain=1#L52-L53)).

**Routed methods.** Exactly 23 methods are routed; any other path fails with `UNIMPLEMENTED` and the message `local method is not supported: <path>` ([`local.rs#L358-L360`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L358-L360)).

- `PushChanges` and `PullChanges` refuse caller-supplied `auth_headers` or `remote_url` with `INVALID_ARGUMENT` ([`local.rs#L413-L423`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L413-L423)). `LocalService` resolves the remote (the named one, else the default, else `origin`), checks push credentials, and mints the outbound headers itself ([`local.rs#L364-L410`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L364-L410)). Credential failures map to `INTERNAL`, `UNAUTHENTICATED` or `PERMISSION_DENIED` ([`local.rs#L425-L433`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L425-L433)). [SyncService](services/sync.md#push-and-pull-credentials) compares the two credential paths field by field. `CONTRACT.md` describes the same boundary ([`CONTRACT.md#L119-L135`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L119-L135)).

### Node addon

With the `node` Cargo feature, libatomic exports a Node-API addon from the same crate, which builds as both an `rlib` and a `cdylib` ([`Cargo.toml#L11-L16`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/Cargo.toml#L11-L16); [`README.md#L106-L116`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/README.md?plain=1#L106-L116)). The addon holds one process-wide `LocalService` ([`node.rs#L11`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/node.rs#L11)) and exports two functions:

- `call(method: string, request: Buffer): Promise<Buffer>`, which forwards to `LocalService::call`. A failure becomes a Node-API `GenericFailure` whose message is the tonic status code and message joined by `": "`; the numeric gRPC code is not exposed separately ([`node.rs#L13-L25`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/node.rs#L13-L25)).
- `descriptor(): Buffer`, which returns `FILE_DESCRIPTOR_SET` ([`node.rs#L27-L30`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/node.rs#L27-L30)).

## Open questions

- **Socket location and listener configuration.** libatomic says the `atomicd` shell serves a private Unix-domain socket ([`mod.rs#L3-L5`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/mod.rs#L3-L5)) but defines neither the socket path nor the listener ([`lib.rs#L22-L24`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/lib.rs#L22-L24)). Within the same workspace a separate client crate owns the socket location and connect logic; it is outside libatomic and is not documented here. Named-pipe, TLS and iroh endpoints are named in the contract only ([`README.md#L3-L4`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/README.md?plain=1#L3-L4)).
- **Version header enforcement.** `CONTRACT.md` requires `x-atomic-contract-version: 2` and failure before dispatch ([`CONTRACT.md#L34-L38`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L34-L38)), but no libatomic code checks it. Whether `atomicd` enforces it, and with which status (the contract's `ERROR_CODE_PROTOCOL_VERSION_MISMATCH` maps to `INTERNAL`, [`state.rs#L443`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L443)), is decided outside libatomic.
- **Message-size limits.** `GetCapabilities` advertises a 64 MiB `max_message_bytes` ([`services.rs#L226-L227`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L226-L227)), and the example client raises its own decode limit to match ([`agent_sandbox_bench.rs#L446`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/examples/agent_sandbox_bench.rs#L446)). `build.rs` configures no limits ([`build.rs#L42-L45`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/build.rs#L42-L45)). The server's encode and decode limits are set by the shell and are not visible in libatomic.
- **Compression.** Nothing in libatomic enables or requires gRPC compression ([`build.rs#L42-L45`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/build.rs#L42-L45)). Whether `atomicd` accepts compressed messages is not stated.
- **Bearer authentication.** The contract specifies `authorization: Bearer` with audience verification for remote identities ([`CONTRACT.md#L43-L46`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L43-L46)), but no libatomic code validates such a token. How `atomicd` or a hosted server authenticates remote identities, and how it maps a Unix-socket peer to `CALLER_CLASS_LOCAL`, is not in libatomic.
- **Server reflection.** The proto comment names a `harness_reflection` feature token and says grpcurl with server reflection is the recommended harness ([`daemon_messages.proto#L92-L94`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/daemon/daemon_messages.proto#L92-L94); [`README.md#L154`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/README.md?plain=1#L154)). `GetCapabilities` does not advertise it ([`services.rs#L221-L225`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L221-L225)) and libatomic depends on no reflection service ([`Cargo.toml#L32-L35`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/Cargo.toml#L32-L35)).
- **Replay.** The contract's replay and `IDEMPOTENCY_MISMATCH` semantics ([`common.proto#L8-L17`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/common/common.proto#L8-L17)) are not implemented in libatomic ([`services_agent.rs#L1233-L1239`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L1233-L1239)). Whether the shell adds them is not stated.
- **Contract size.** The README and `COVERAGE.md` say 94 rpcs and the crate documentation 97 ([`README.md#L43`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/README.md?plain=1#L43); [`lib.rs#L7-L8`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/lib.rs#L7-L8)); the service protos declare 105. The documents are stale; the protos are authoritative.
