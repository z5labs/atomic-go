# RepositoryMutationService

RepositoryMutationService carries the working-copy and change-graph mutations behind the CLI's `add`, `remove`, `move`, `restore`, `record`, `revise`, `insert`, `unrecord` and `stash` commands [`COVERAGE.md#L140-L145`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/COVERAGE.md?plain=1#L140-L145) [`COVERAGE.md#L149-L150`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/COVERAGE.md?plain=1#L149-L150) [`COVERAGE.md#L152`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/COVERAGE.md?plain=1#L152). The service definition is marked DRAFT and add-only [`repository_mutation_service.proto#L1-L3`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/repository_mutation/repository_mutation_service.proto#L1-L3). Every rpc has a handler in `MutationImpl` [`services.rs#L1407-L1408`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1407-L1408). At this commit eight handlers are marked implemented and four partial: MoveFile refuses directories, and Revise, InsertChanges and Unrecord ignore request fields that the contract gives meaning to (see each method).

The messages file states the intended model: every mutation carries a RequestMeta idempotency key and, where the caller knows prior state, an ExpectedState precondition; mutations commit their repository event to the outbox in the same write transaction; writes queue per repository and working-copy mutations also hold the workspace lease [`repository_mutation_messages.proto#L4-L11`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/repository_mutation/repository_mutation_messages.proto#L4-L11). The handlers at this commit implement less than that. The points below apply to every method.

- **Repository resolution.** When `repository` is absent, a handler substitutes an empty `RepositoryRef` [`services.rs#L1138-L1144`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1138-L1144) and resolves it with `DaemonState::resolve`, which refuses any authority other than `local` and any `repository_id` not registered with this daemon [`state.rs#L329-L348`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L329-L348). Send the reference that [ResolveRepository](./daemon.md#resolverepository) returned.
- **Serialization.** Every handler, ListStashes included, takes the repository's exclusive gate before any domain work (for example [`services.rs#L1418-L1419`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1418-L1419) and [`services.rs#L2862-L2863`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L2862-L2863)). The gate allows one open database handle per repository within the process [`state.rs#L54-L58`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L54-L58).
- **Workspace entry.** Handlers that touch the working copy open a workspace transaction, in `Observe` mode for a dry run and `Reconcile` mode otherwise (for example [`services.rs#L1431-L1435`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1431-L1435)). `Reconcile` first refuses a workspace that needs reconciliation [`state.rs#L142-L159`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L142-L159); a contended workspace lock is retried until the database-open deadline [`state.rs#L196-L206`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L196-L206), which `ATOMIC_DB_LOCK_WAIT_MS` overrides [`state.rs#L26-L33`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L26-L33).
- **RequestMeta and idempotency.** The contract requires a nonempty UUID `request_id` on ordinary mutations, replay keyed on it, and `IDEMPOTENCY_MISMATCH` when a reused key carries different contents [`CONTRACT.md#L54-L58`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L54-L58). No handler in this service checks, stores or replays `request_id`. AddFiles and Record only echo it with `replayed = false` [`services.rs#L1490-L1494`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1490-L1494) [`services.rs#L1664-L1668`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1664-L1668); the other methods return no ResponseMeta at all (for example [`services.rs#L1851-L1858`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1851-L1858)). A repeated request runs again.
- **Fences.** Only Record and InsertChanges read a precondition, and both accept a request without one ([`services.rs#L1570-L1572`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1570-L1572), [`services.rs#L2306-L2310`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L2306-L2310)), although the contract says view-dependent mutations require the matching snapshot and that absence is a domain precondition failure [`CONTRACT.md#L312-L316`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L312-L316). AddFiles, Revise and Unrecord declare an `expected` field that no handler code reads.
- **Capability advertisement.** All twelve methods are in METHOD_MATRIX [`services.rs#L73-L84`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L73-L84), but GetCapabilities describes each of them with scope `EXECUTION_SCOPE_BOTH` and empty capability, caller and effect lists [`services.rs#L204-L213`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L204-L213), not the method options shown in the tables below.
- **Transport.** The in-process LocalService routes only AddFiles, Record and InsertChanges [`local.rs#L124-L153`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L124-L153). Contract-version metadata, authentication and caller-class checks are transport concerns; see [version negotiation](../transport.md#version-negotiation) and [authentication and authorization](../transport.md#authentication-and-authorization).

**Behaviour**

- An already-tracked or ignored path never fails the request, in either mode [`services.rs#L1467-L1474`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1467-L1474).
- Outside a dry run, an unexpected error on one path fails the request after the earlier paths were already passed to the domain [`services.rs#L1444-L1481`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1444-L1481). Whether their tracking survives the failure is not shown in libatomic (see [Open questions](#open-questions)).
- The skip and failure lists are complete only in a dry run; outside one, only `tracked` and the error-derived skips are filled [`services.rs#L1451-L1477`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1451-L1477).

**Behaviour**

- A mutation with any refusal applies nothing and returns OK with the refusals and `removed = 0`, so the caller can fix the request and rerun [`services.rs#L1772-L1805`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1772-L1805). A client must inspect `refusals`, not only the status.
- The uncommitted-edits check fails closed: when the domain cannot compute a path's status, the path is refused [`services.rs#L1756-L1759`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1756-L1759).
- Deletion paths are resolved against the repository root, never the daemon's working directory [`services.rs#L1808-L1812`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1808-L1812). A directory is deleted recursively and a path already absent counts as deleted [`services.rs#L42-L50`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L42-L50).
- With `keep_working_copy` false, the path deleted is the requested path itself [`services.rs#L1825-L1827`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1825-L1827). A successful deletion of such a path is not reported in any field; only a failure appears, in `failed_deletions` [`services.rs#L1837-L1841`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1837-L1841).
- An error in the apply phase fails the request after earlier paths were already untracked by the domain [`services.rs#L1816-L1820`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1816-L1820); see [Open questions](#open-questions).

**Behaviour**

- **Fence.** With `merkle_root`, the hash must equal the workspace view's own state. With `view_snapshot`, the snapshot's view name defaults to the workspace view and must match it, and `own_merkle` (or, if absent, `effective_state`) must equal the view's own state [`services.rs#L1178-L1224`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1178-L1224). The response's `view_merkle` is the next call's expected state [`services.rs#L1166-L1171`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1166-L1171); a stale one is refused with `VIEW_STALE` and an unsupported form with `INVALID_ARGUMENT` [`record_service_test.rs#L269-L292`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/record_service_test.rs#L269-L292).
- **Fence ordering.** The fence is checked on a read-only handle before workspace entry, so a stale request is refused before reconciliation can capture pending work, and again under the workspace lease to catch intervening writes [`services.rs#L1529-L1540`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1529-L1540) [`services.rs#L1566-L1572`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1566-L1572). A test checks that a stale record leaves every file under `.atomic` unchanged [`record_service_test.rs#L383-L436`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/record_service_test.rs#L383-L436).
- **Oversized files.** When the recorder refuses a file as too large, the status carries `atomic-record-error: file-too-large`, the raw path bytes in binary metadata `atomic-file-path-bin`, and `atomic-file-size` and `atomic-file-limit` as decimal text [`services.rs#L1594-L1613`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1594-L1613). A test checks the view state and the working-copy bytes are unchanged after this error [`record_service_test.rs#L96-L146`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/record_service_test.rs#L96-L146).
- **Authorship.** An explicit `author` wins; else `identity_name` from the serving host's identity store; else that store's default identity; else none [`services.rs#L1382-L1405`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1382-L1405) [`services.rs#L1154-L1164`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1154-L1164). The identity store is the server host's, not the caller's [`repository_mutation_messages.proto#L115-L116`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/repository_mutation/repository_mutation_messages.proto#L115-L116).
- **Idempotency.** `request_id` is echoed, not deduplicated; a retried Record records again (see the overview).

**Behaviour**

- **Fence.** The snapshot's view name defaults to the target and must match it. When `own_merkle` is set it must equal the view's own state; otherwise `effective_state` must equal the view's effective state [`services.rs#L1228-L1277`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1228-L1277). The fence is checked before workspace entry, so a stale request is refused before reconciliation captures work, and again after entry [`services.rs#L2271-L2287`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L2271-L2287) [`services.rs#L2301-L2310`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L2301-L2310); a test checks that a stale insert leaves `.atomic` unchanged [`record_service_test.rs#L383-L436`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/record_service_test.rs#L383-L436). Dry runs are not fenced [`services.rs#L2304-L2306`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L2304-L2306).
- **Fence target.** The fence is checked against `target_view` or, when it is absent, the current view [`services.rs#L2279-L2284`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L2279-L2284) [`services.rs#L2297-L2308`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L2297-L2308). For a promotion without `target_view`, that is the source view, not the parent the changes land in [`services.rs#L2469-L2481`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L2469-L2481).
- **Dirty working copy.** When the target is the current view and the source is not a promotion, the handler refuses to run over unrecorded changes, including untracked files [`services.rs#L2313-L2334`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L2313-L2334). Conflicted files whose bytes, kind and mode still match the view's canonical render are allowed; any other non-clean status counts as unrecorded work [`services.rs#L1279-L1311`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1279-L1311) [`services.rs#L1350-L1379`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1350-L1379).
- **Working-copy refresh.** After a successful non-dry-run insert that applied at least one change into the workspace's current view, the handler refreshes the working copy: `from_view` and `up_to_tag` rewrite the touched paths, `single_change`, `single_ref` and `change_set` rematerialize the whole view, and promotion never refreshes [`services.rs#L2599-L2628`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L2599-L2628). An insert into a view that is not checked out leaves host files untouched [`local_service_test.rs#L1086-L1111`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/local_service_test.rs#L1086-L1111).
- **Authority.** The method is declared for both scopes and for remote identities, but this handler serves only the `local` authority [`state.rs#L332-L340`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L332-L340).

## Open questions

- **Idempotency is not implemented.** The contract requires a nonempty UUID `request_id`, replay and `IDEMPOTENCY_MISMATCH` [`CONTRACT.md#L54-L58`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L54-L58), and says ResponseMeta is present on every successful ordinary mutation response [`common.proto#L111-L117`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/common/common.proto#L111-L117). These handlers neither check nor replay `request_id` [`services.rs#L1490-L1494`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1490-L1494), and ten of the twelve return no ResponseMeta (for example [`services.rs#L2660`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L2660)). It is unclear whether a middleware layer outside libatomic is meant to supply replay, or whether clients should treat every mutation as non-idempotent.
