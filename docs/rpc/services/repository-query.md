# RepositoryQueryService

RepositoryQueryService holds Atomic's read-only repository operations: working-copy status, change history, single-change lookup, view-to-view and working-copy diffs, mutation previews, and the conflict listing. The message file describes LOCAL-scoped reads as working-copy-aware and BOTH-scoped reads as meant to behave identically on the local daemon and a hosted server [`repository_query_messages.proto#L1-L8`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/repository_query/repository_query_messages.proto#L1-L8). Both proto files are marked DRAFT and add-only [`repository_query_service.proto#L1-L3`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/repository_query/repository_query_service.proto#L1-L3).

All eight rpcs have handlers in `QueryImpl` [`services.rs#L340-L345`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L340-L345); GetChange and DiffWorkingCopy delegate to `services_query.rs` [`services.rs#L501-L506`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L501-L506) [`services.rs#L558-L567`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L558-L567). No handler returns `Unimplemented`. Six of the eight are listed in `METHOD_MATRIX` [`services.rs#L67-L72`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L67-L72); GetChange and DiffWorkingCopy are not. For every listed method of this service, GetCapabilities builds the descriptor in its generic branch, which reports `EXECUTION_SCOPE_BOTH` and empty capability, caller and effect lists [`services.rs#L204-L212`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L204-L212), so the advertised descriptor does not repeat the proto method options shown below. The in-process [LocalService](../transport.md#in-process-localservice) routes Status, Log, GetChange and PreviewRestore [`local.rs#L111-L123`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L111-L123) [`local.rs#L218-L247`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L218-L247); every other method of this service gets `Unimplemented` from it [`local.rs#L358-L360`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L358-L360).

## Common behaviour

These points apply to every method on this page. Method sections refer back here instead of repeating them.

**Repository resolution.** Each handler turns `repository` into a registered repository through `DaemonState::resolve`. An `authority` other than `"local"` fails with INVALID_ARGUMENT, and a `repository_id` that this daemon (or this `LocalService` instance) has not registered fails with NOT_FOUND [`state.rs#L329-L348`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L329-L348). Status, Log, Diff, ListConflicts, PreviewMutation and PreviewRestore substitute an empty `RepositoryRef` when the field is absent [`services.rs#L1138-L1144`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1138-L1144), so an absent reference fails the authority check with INVALID_ARGUMENT. GetChange and DiffWorkingCopy call `unwrap()` on the field instead [`services_query.rs#L28`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L28) [`services_query.rs#L314`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L314); see Open questions. `resolve` never reads `workspace_id` [`state.rs#L331-L347`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L331-L347).

**Serialization gate.** Each registered repository has one async mutex. A handler that holds it excludes every other gated request on the same repository for the duration of the call [`state.rs#L35-L58`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L35-L58). Status, Log, GetChange and DiffWorkingCopy take the gate [`services.rs#L356-L357`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L356-L357) [`services.rs#L410-L411`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L410-L411) [`services_query.rs#L325-L326`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L325-L326) [`services_query.rs#L37-L38`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L37-L38). Diff, ListConflicts and PreviewRestore are documented in the handler as not taking it [`services.rs#L530-L531`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L530-L531) [`services.rs#L578-L579`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L578-L579) [`services.rs#L827`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L827), and PreviewMutation's handler body contains no gate acquisition [`services.rs#L612-L626`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L612-L626).

**Default view.** Where Log and PreviewMutation fall back to "the current view", they use `RepoHandle::current_view`, which reads the `.atomic/current_view` marker file and falls back to `"dev"` when it cannot be read [`state.rs#L77-L85`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L77-L85). GetChange instead falls back to the opened repository's own current view [`services_query.rs#L347-L349`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L347-L349) [`services_query.rs#L451`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L451). A libatomic test states that the marker file is derived, not authoritative [`query_view_service_test.rs#L56-L57`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/query_view_service_test.rs#L56-L57).

**Idempotency and snapshots.** No request message of this service carries a `RequestMeta`, and PreviewMutation is declared to make no RequestMeta or replay writes [`repository_query_service.proto#L56`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/repository_query/repository_query_service.proto#L56). No handler of this service sets a `ViewSnapshot` in its response [`services.rs#L396`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L396) [`services.rs#L673`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L673) [`services.rs#L888`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L888).

**Errors.** Handler refusals are built with `domain_status`, which maps the [ErrorCode](../errors.md#errorcode) to a gRPC code and prefixes the message with `atomic:<CODE>: ` [`state.rs#L432-L452`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L432-L452); see [how handlers produce errors](../errors.md#how-handlers-produce-errors). Two mappings matter for this service: ERROR_CODE_VIEW becomes PERMISSION_DENIED [`state.rs#L442`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L442), and ERROR_CODE_REPOSITORY becomes INTERNAL [`state.rs#L444`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L444). Every domain error passed through `repository_error` becomes ERROR_CODE_REPOSITORY [`state.rs#L455-L459`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L455-L459). ## Methods

### Status

`rpc Status(StatusRequest) returns (StatusResponse)`, unary [`repository_query_service.proto#L13-L22`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/repository_query/repository_query_service.proto#L13-L22).

Status returns the working-copy status of one repository: the view, its Merkle state, one entry per reported file, and per-status counts [`repository_query_messages.proto#L40-L57`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/repository_query/repository_query_messages.proto#L40-L57). The handler enters an observe-mode workspace transaction, runs the domain status computation with the caller's options, and maps each entry to the wire shape [`services.rs#L358-L397`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L358-L397). It never reindexes: `--reindex` is a separate `MaintenanceService.ReindexWorkspace` call followed by Status [`repository_query_service.proto#L13-L14`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/repository_query/repository_query_service.proto#L13-L14), the old `allow_reindex` field 2 is reserved [`repository_query_messages.proto#L22`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/repository_query/repository_query_messages.proto#L22), and the contract repeats that Status does not reindex [`CONTRACT.md#L331`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L331).
