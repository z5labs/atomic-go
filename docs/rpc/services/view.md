# ViewService

ViewService manages the lifecycle and scope of views, which the proto calls the workflow spine (draft to shared). View reads and repository-only lifecycle writes are declared BOTH; the message file says only switch follows a host working copy and stays LOCAL [`view_messages.proto#L1-L5`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/view/view_messages.proto#L1-L5), although SplitView is LOCAL as well [`view_service.proto#L63`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/view/view_service.proto#L63). Both proto files are marked DRAFT and add-only [`view_service.proto#L1-L3`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/view/view_service.proto#L1-L3).

All six rpcs have handlers in `ViewImpl` [`services_query.rs#L744-L753`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L744-L753), and none returns `Unimplemented`. All six are listed in `METHOD_MATRIX` [`services.rs#L113-L118`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L113-L118); GetCapabilities builds their descriptors in its generic branch, which reports `EXECUTION_SCOPE_BOTH` and empty capability, caller and effect lists [`services.rs#L204-L212`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L204-L212), so the advertised descriptor does not repeat the proto method options shown below. The in-process [LocalService](../transport.md#in-process-localservice) routes ListViews, CreateView, SwitchView and DeleteView [`local.rs#L248-L287`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L248-L287); SetViewScope and SplitView get `Unimplemented` from it [`local.rs#L358-L360`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L358-L360).

## Common behaviour

These points apply to every method on this page. Method sections refer back here instead of repeating them.

**Repository resolution.** Every handler calls `unwrap()` on `repository` before resolving it [`services_query.rs#L759`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L759) [`services_query.rs#L814`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L814) [`services_query.rs#L899`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L899) [`services_query.rs#L950`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L950) [`services_query.rs#L996`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L996) [`services_query.rs#L1034`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L1034), so a request without one panics inside the handler; see Open questions. `LocalService` rejects an absent `repository` with INVALID_ARGUMENT before calling the handler [`local.rs#L435-L440`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L435-L440). Resolution fails with INVALID_ARGUMENT when `authority` is not `"local"` and with NOT_FOUND when `repository_id` is not registered with this daemon or `LocalService` instance [`state.rs#L329-L348`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L329-L348). `workspace_id` is not read [`state.rs#L331-L347`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L331-L347).

**Serialization gate.** Every handler takes the repository's gate for the whole call [`services_query.rs#L761-L762`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L761-L762) [`services_query.rs#L816-L817`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L816-L817) [`services_query.rs#L901-L902`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L901-L902) [`services_query.rs#L952-L953`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L952-L953) [`services_query.rs#L998-L999`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L998-L999) [`services_query.rs#L1036-L1037`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L1036-L1037), so view calls are serialized with every other gated request on the same repository [`state.rs#L35-L58`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L35-L58).

**View names.** CreateView, SwitchView, DeleteView and SetViewScope trim surrounding whitespace from the view name before using it [`services_query.rs#L822`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L822) [`services_query.rs#L905`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L905) [`services_query.rs#L957`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L957) [`services_query.rs#L1003`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L1003); SplitView does not [`services_query.rs#L1057`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L1057).

**View identity.** Every `ViewRef` these handlers return has `view_id` set to the BLAKE3 hash of the view name [`services_query.rs#L792-L795`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L792-L795) [`services_query.rs#L884-L887`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L884-L887) [`services_query.rs#L1129-L1132`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L1129-L1132). The shared message describes `view_id` as a stable identity that deleting and recreating a name never revives [`common.proto#L68-L70`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/common/common.proto#L68-L70); with a name-derived ID, a recreated view gets the same `view_id`.

**Current view.** `ViewInfo.current` compares the view name with `RepoHandle::current_view` [`services_query.rs#L777`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L777) [`services_query.rs#L791`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L791), which reads the `.atomic/current_view` marker file and falls back to `"dev"` [`state.rs#L77-L85`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L77-L85). A libatomic test states that the marker is derived, not authoritative [`query_view_service_test.rs#L56-L57`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/query_view_service_test.rs#L56-L57). DeleteView's protection of the current view uses the working copy's registered view instead [`services_query.rs#L958-L969`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L958-L969).

**Idempotency and fencing.** No handler of this service reads `RequestMeta`, and every response leaves `meta` unset [`services_query.rs#L890`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L890) [`services_query.rs#L941`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L941) [`services_query.rs#L988`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L988) [`services_query.rs#L1026`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L1026) [`services_query.rs#L1135`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L1135). The contract requires a non-empty UUID `request_id` on ordinary mutations and `ResponseMeta` at field 100 on their responses [`CONTRACT.md#L54-L58`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L54-L58). No handler reads the snapshot or expected-state fields (`base_snapshot`, `expected`, `expected_snapshot`), although the contract says view-dependent mutations require the matching snapshot [`CONTRACT.md#L312-L316`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L312-L316). A retried CreateView therefore meets the view it created and fails with PERMISSION_DENIED instead of replaying [`services_query.rs#L824-L829`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L824-L829).

**Errors.** Handler refusals are built with `domain_status`, which maps the [ErrorCode](../errors.md#errorcode) to a gRPC code and prefixes the message with `atomic:<CODE>: ` [`state.rs#L432-L452`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L432-L452); see [how handlers produce errors](../errors.md#how-handlers-produce-errors). ### CreateView
