# SandboxService

SandboxService has three groups of methods: grant administration (`OpenSandbox`, `RenewSandbox`, `CloseSandbox`), local copy-on-write sandbox working trees and OCI images (`CreateSandboxTree`, `StageSandboxImage`, `SealSandboxImage`), and the remote-sandbox data operations (`Materialize`, `GetFileStates`, `GetChanges`, `PublishProvenance`, `SubmitChange`, `SubmitAttestation`) [`services_sandbox.rs#L1-L14`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L1-L14). A remote sandbox is a machine that holds only a pointer file, `.atomic-sandbox`, naming the serving daemon, the repository, the view and the token; `Materialize` writes the view's tree into the sandbox root, and changes recorded there land through the serving repository [`sandbox_messages.proto#L7-L11`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/sandbox/sandbox_messages.proto#L7-L11).

## Callers, grants and tokens

Every method below depends on the rules in this section.

**Who is calling.** A handler classifies the caller from the request itself [`sandbox_grants.rs#L563-L573`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L563-L573):

- A `SandboxGrant` that the host attached to the request's extensions is a sandbox principal the host has already verified; the handler still checks its expiry [`sandbox_grants.rs#L574-L582`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L574-L582).
- Otherwise a token in the binary metadata key `x-atomic-sandbox-token-bin` [`sandbox_grants.rs#L38-L39`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L38-L39) is resolved through the grant store [`sandbox_grants.rs#L597-L604`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L597-L604).
- A request with neither is a local, trusted caller. The host must not let an untrusted caller reach the handlers without one [`sandbox_grants.rs#L19-L20`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L19-L20).
- More than one token value, or a token beside an `authorization` header, is refused with `UNAUTHORIZED` [`sandbox_grants.rs#L583-L593`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L583-L593).

The contract puts the token in `x-atomic-sandbox-token-bin` on all sandbox calls, including calls to other services; other remote identities use `authorization: Bearer ...`, and tokens in request bodies are retired [`CONTRACT.md#L43-L47`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L43-L47). The data-op requests reserve the field numbers that once carried credentials [`sandbox_messages.proto#L214`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/sandbox/sandbox_messages.proto#L214). The libatomic test client sends the token bytes exactly as `OpenSandbox` returned them, as binary metadata [`sandbox_service_test.rs#L193-L200`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/sandbox_service_test.rs#L193-L200). Version negotiation (`x-atomic-contract-version`) is a transport concern [`CONTRACT.md#L34-L38`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L34-L38); see [version negotiation](../transport.md#version-negotiation).

**Local-only methods.** The grant-administration and working-tree handlers call `local_only`, which refuses a request that carries a host-attached grant or a sandbox token with `FORBIDDEN` [`sandbox_grants.rs#L607-L617`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L607-L617). It inspects nothing else, so a remote identity that sends an `authorization` header and no sandbox token is not refused by the handler. The contract makes the serving side reject network principals on local-only methods [`CONTRACT.md#L26-L30`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L26-L30); see [authentication and authorization](../transport.md#authentication-and-authorization).

**Which methods a sandbox may call.** A host should dispatch a sandbox principal only to the methods in `SANDBOX_SCOPED_METHODS`, the part of the sandbox allowlist whose handlers enforce the grant's scope themselves [`sandbox_grants.rs#L105-L109`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L105-L109). From this service that list holds the six data operations and none of the administration or working-tree rpcs [`sandbox_grants.rs#L113-L118`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L113-L118).

**What a grant holds.** One repository, one view together with the repository's internal id for that view at issue, an optional acting identity, a non-empty capability set, and an expiry on the server clock [`sandbox_grants.rs#L142-L158`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L142-L158). The only capabilities a grant may carry are `sandbox.read`, `sandbox.submit`, `provenance.read`, `provenance.write`, `agent.checkpoint`, `vault.read`, `vault.write`, `knowledge.read`, `attestation.read` and `attestation.write` [`sandbox_grants.rs#L49-L62`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L49-L62). The contract forbids delegating repository, working-copy, view-lifecycle, daemon, maintenance, sync, Reactor, Git-interop or `sandbox.admin` rights, and calls an empty permission set invalid [`CONTRACT.md#L152-L155`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L152-L155).

**One live token per view.** Minting a token for a (repository, view) pair removes every other grant for that pair [`sandbox_grants.rs#L394-L398`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L394-L398). Renewing changes only the expiry, closing revokes, and resolving refuses a replaced, revoked or expired token [`sandbox_grants.rs#L261-L264`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L261-L264). A replaced or revoked token resolves as unknown and an expired one as expired; both are `UNAUTHORIZED` [`sandbox_grants.rs#L211-L221`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L211-L221) [`sandbox_grants.rs#L429-L440`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L429-L440).

**Token storage and lifetime.** The default store, `InMemorySandboxGrants`, keys grants by the BLAKE3 hash of the token [`sandbox_grants.rs#L313-L318`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L313-L318) [`sandbox_grants.rs#L342-L344`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L342-L344) and lives only in memory: when the process ends every token fails closed and the local administrator reissues [`sandbox_grants.rs#L320-L322`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L320-L322). A host may install its own store, for example to persist grants [`state.rs#L301-L307`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L301-L307). The proto contract says no durable response, outbox or event payload may contain the token, and that a restart invalidating all tokens is documented behaviour, not an outage [`sandbox_messages.proto#L388-L395`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/sandbox/sandbox_messages.proto#L388-L395). The token is available only once, in the `OpenSandbox` response [`sandbox_grants.rs#L268-L271`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L268-L271). The default store issues `ast_` followed by the unpadded base64url encoding of 32 random bytes [`sandbox_grants.rs#L383-L385`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L383-L385), but tokens are opaque bytes on the wire [`sandbox_messages.proto#L405-L406`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/sandbox/sandbox_messages.proto#L405-L406).

**TTL.** A grant lasts from 1 to 31,536,000 seconds (365 days), 7,200 seconds by default [`sandbox_grants.rs#L41-L47`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L41-L47). The deadline is computed with checked arithmetic; an out-of-range value is an error, never a panic [`sandbox_grants.rs#L224-L235`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L224-L235).

**Revalidation after queueing.** Each data operation waits for the repository's exclusive gate and then resolves the grant again, so a grant that expired or was revoked while the request was queued writes nothing [`services_sandbox.rs#L782-L789`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L782-L789) [`sandbox_grants.rs#L543-L555`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L543-L555). The contract requires this re-check at publication [`CONTRACT.md#L48-L51`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L48-L51).

**Deleted and recreated views.** A grant records the view's internal id. Each data operation checks that the view still exists and still has that id, so deleting a view and recreating its name does not revive the grant: the request is refused with `FORBIDDEN` [`services_sandbox.rs#L143-L168`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L143-L168) [`sandbox_service_test.rs#L1022-L1042`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/sandbox_service_test.rs#L1022-L1042).

**Sessions.** Provenance sessions and turns a sandbox starts are bound to its grant's view [`sandbox_grants.rs#L4-L7`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L4-L7). Ownership is recorded per (repository, view), so a reissued token for the same view keeps its sessions and a token for another view never gains them [`sandbox_grants.rs#L264-L267`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L264-L267). A sandbox's view claims a session when it reserves a turn in a session nothing has been recorded for, through [ReserveTurn](./provenance.md#reserveturn) [`sandbox_messages.proto#L16-L18`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/sandbox/sandbox_messages.proto#L16-L18) [`sandbox_grants.rs#L288-L296`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L288-L296). A session the host already wrote to, or another view's session, cannot be claimed [`sandbox_service_test.rs#L1267-L1280`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/sandbox_service_test.rs#L1267-L1280).

**Naming the view.** A data operation from a sandbox acts on the grant's view. `target` may be omitted; if present, its `name` (when set) and its `view_id` (when non-empty) must both match the grant's view, and the request must name the grant's repository with no `workspace_id`, or it is refused with `FORBIDDEN` [`services_sandbox.rs#L123-L141`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L123-L141) [`sandbox_grants.rs#L506-L541`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L506-L541). A local caller must set `target.name`; `view_id` alone is not enough [`services_sandbox.rs#L107-L121`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L107-L121) [`services_sandbox.rs#L139`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L139). The `view_id` the handlers issue and accept is the BLAKE3 hash of the view name [`sandbox_grants.rs#L558-L561`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L558-L561) [`sandbox_wire.rs#L65-L71`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_wire.rs#L65-L71).

## Snapshots and fencing

The handlers build a [ViewSnapshot](../types.md#viewsnapshot) from the view's effective state, which is the fence, and its own Merkle state, which is diagnostic [`sandbox_wire.rs#L73-L81`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_wire.rs#L73-L81). A fence compares only `effective_state`, which must be a 32-byte BLAKE3 [Hash](../types.md#hash) [`sandbox_wire.rs#L83-L87`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_wire.rs#L83-L87) [`sandbox_wire.rs#L37-L48`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_wire.rs#L37-L48); the `view` and `own_merkle` of a snapshot the client sends are not read. `GetFileStates` and `GetChanges` refuse a mismatched snapshot with `VIEW_STALE` as a gRPC error [`services_sandbox.rs#L181-L192`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L181-L192). `SubmitChange` instead returns the refusal in its response body together with the view's live skeleton [`services_sandbox.rs#L818-L827`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L818-L827). The libatomic test client takes the fence from `Materialize`'s summary skeleton and, after each accepted `SubmitChange`, from that response's `ResponseMeta.snapshot` [`sandbox_service_test.rs#L510-L517`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/sandbox_service_test.rs#L510-L517) [`sandbox_service_test.rs#L298-L305`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/sandbox_service_test.rs#L298-L305).

**Behaviour**

- The handler holds the repository's exclusive gate while it looks up the view and its snapshot [`services_sandbox.rs#L227-L238`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L227-L238).
- It is not idempotent. Every call mints a new random token and removes the previous grant for the view [`sandbox_grants.rs#L383-L398`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L383-L398), whose token is then refused with `UNAUTHORIZED` [`sandbox_service_test.rs#L990-L997`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/sandbox_service_test.rs#L990-L997). `request_id` is only echoed, never replayed [`services_agent.rs#L1233-L1239`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L1233-L1239). The contract says grant-administration replay lives only in memory and that local administration mints a fresh grant with a new request ID [`CONTRACT.md#L60-L64`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L60-L64).

- The handler holds the repository gate and a reconciling workspace transaction for the whole operation [`services_sandbox.rs#L322-L334`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L322-L334).

- It is not idempotent: a repeated call fails because the destination exists [`services_sandbox.rs#L338-L343`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L338-L343). With `from_view`, the draft is created before provisioning, and the handler does not remove it if provisioning then fails [`services_sandbox.rs#L347-L357`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L347-L357).

**What a client must do**

- Validate every `TreeEntry.path` before writing it. Paths off the wire must be plain relative components (no `..`, no root, no empty or `.` component); the bookkeeping names are refused, because writing the pointer file would re-point the sandbox at an attacker's node; and each parent must be canonicalized and checked to be inside the tree, which refuses a symlinked-parent escape [`sandbox_messages.proto#L28-L33`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/sandbox/sandbox_messages.proto#L28-L33) [`sandbox_messages.proto#L231-L232`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/sandbox/sandbox_messages.proto#L231-L232). The bookkeeping names are `.atomic`, `.atomic-sandbox` and `.atomic-sandbox.d` [`services_sandbox.rs#L82-L84`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L82-L84). The contract keeps these lexical, reserved-name, symlink-parent and final-write checks on the client [`CONTRACT.md#L321-L322`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L321-L322).
- Treat a stream that ends without `done` as a failure, and check that `done.entries` equals the number of entries received. Both libatomic clients do [`sandbox_service_test.rs#L510-L511`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/sandbox_service_test.rs#L510-L511) [`sandbox_service_test.rs#L533`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/sandbox_service_test.rs#L533) [`agent_sandbox_bench.rs#L489-L494`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/examples/agent_sandbox_bench.rs#L489-L494) [`agent_sandbox_bench.rs#L507-L513`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/examples/agent_sandbox_bench.rs#L507-L513).
- Write file content from `inline`. Both libatomic clients pass every entry through the path-checked entry writer, using `inline` as the content and mode `0644` when `mode` is absent [`sandbox_service_test.rs#L498-L508`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/sandbox_service_test.rs#L498-L508) [`agent_sandbox_bench.rs#L496-L506`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/examples/agent_sandbox_bench.rs#L496-L506).
- Create parent directories on write. With a prefix, only the leading directories that the view has are streamed, not a synthesized chain [`sandbox_service_test.rs#L1188-L1200`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/sandbox_service_test.rs#L1188-L1200).
- Keep the summary skeleton for later calls. `skeleton.graph_slice` is what a cache imports [`sandbox_messages.proto#L72-L76`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/sandbox/sandbox_messages.proto#L72-L76) [`sandbox_wire.rs#L169-L176`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_wire.rs#L169-L176), and `skeleton.snapshot` is the fence for `GetFileStates`, `GetChanges` and `SubmitChange` ([Snapshots and fencing](#snapshots-and-fencing)).
- Materialize again after a stale refusal [`services_sandbox.rs#L186-L189`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L186-L189) [`sandbox_service_test.rs#L701-L714`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/sandbox_service_test.rs#L701-L714).
- Allow for large messages: each file's whole content rides inline in its entry [`sandbox_wire.rs#L99-L100`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_wire.rs#L99-L100). **Behaviour**

- A sandbox publishes only for a session its view owns. It claims the session first by reserving a turn through [ReserveTurn](./provenance.md#reserveturn) [`sandbox_service_test.rs#L1347-L1361`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/sandbox_service_test.rs#L1347-L1361). The handler checks ownership only for sandbox callers [`services_sandbox.rs#L681-L697`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L681-L697).
- Provenance that explains a change the view cannot see is refused as a whole [`sandbox_service_test.rs#L1368-L1377`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/sandbox_service_test.rs#L1368-L1377).
- Session ownership is checked before the request waits for the repository; after the wait only the grant is checked again [`services_sandbox.rs#L681-L704`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L681-L704).
- The contract has PublishProvenance accept a SessionTurn and `expected_generation` rather than a caller-supplied stored turn, and derive state server-side [`CONTRACT.md#L214-L216`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L214-L216).
- The handler opens and drops the change store before it opens the repository [`services_sandbox.rs#L706-L723`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L706-L723).
- `request_id` is only echoed, never replayed [`services_agent.rs#L1233-L1239`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L1233-L1239).

The handler returns that refusal before it checks session ownership or re-checks the grant [`services_sandbox.rs#L886-L924`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L886-L924).
- A `session_json` without a non-empty `mac_key` is not adopted and `session_state` is `false`; a DID-signed attestation is saved regardless [`services_sandbox.rs#L862-L865`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L862-L865).
- `request_id` is only echoed, never replayed [`services_agent.rs#L1233-L1239`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L1233-L1239).

### Refusals in a response body

Domain refusals that must carry recovery data travel as oneof outcomes in the response, not as gRPC errors [`README.md#L104-L106`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/README.md?plain=1#L104-L106). [GetChanges](#getchanges), [PublishProvenance](#publishprovenance), [SubmitChange](#submitchange) and [SubmitAttestation](#submitattestation) build their refusal [ErrorInfo](../errors.md#errorinfo) with `rejection_error_info` [`sandbox_wire.rs#L242`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_wire.rs#L242). Its codes, its `context["reason"]` values and the context keys of each reason are listed once, under [Refusal ErrorInfo](../errors.md#refusal-errorinfo).

### GrantInfo

A live grant as the registry tracks it: `view` (1), `acting_as_did` (2), `expires_at` (3), `repository` (4), `target` (5) and `capabilities` (6) [`sandbox_messages.proto#L405-L414`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/sandbox/sandbox_messages.proto#L405-L414). No rpc in this service returns it.

## Open questions

- **Panics on an absent `repository`.** `CreateSandboxTree`, `StageSandboxImage` and `SealSandboxImage` unwrap `request.repository` without a check [`services_sandbox.rs#L320`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L320) [`services_sandbox.rs#L385`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L385) [`services_sandbox.rs#L428`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L428), while the grant-administration and data handlers return `INVALID_ARGUMENT` [`services_sandbox.rs#L50-L54`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L50-L54). - **Relative destination paths.** `dest` and `out_dir` become paths exactly as sent [`services_sandbox.rs#L335-L337`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L335-L337) [`services_sandbox.rs#L400`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L400) [`services_sandbox.rs#L442`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L442), so a relative path would resolve against the daemon process's working directory, which the contract says no operation uses [`CONTRACT.md#L115`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L115). - **Unvalidated working-tree fields.** The handlers pass `name`, `base_view` and `out_dir` to the repository without checks [`services_sandbox.rs#L325`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L325) [`services_sandbox.rs#L390-L392`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L390-L392) [`services_sandbox.rs#L433-L434`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L433-L434); what an empty value does is decided outside libatomic.
- **`view_id` is derived from the name.** The contract calls `ViewRef.view_id` a stable, opaque identity that authorization uses, with the name only a display hint [`common.proto#L68-L74`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/common/common.proto#L68-L74). The handlers issue and accept the BLAKE3 hash of the name [`sandbox_grants.rs#L558-L561`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/sandbox_grants.rs#L558-L561) and cannot resolve a view from `view_id` alone [`services_sandbox.rs#L107-L121`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L107-L121); protection against a recreated name comes from the grant's separately recorded internal id [`services_sandbox.rs#L143-L168`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L143-L168). Clients should echo `view_id` rather than compute it, but whether its derivation will change is not stated.
- **Deleting a view.** The proto says deleting a view revokes its grants [`sandbox_messages.proto#L400`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/sandbox/sandbox_messages.proto#L400). - **Materialize prefix matching.** The prefix filter compares strings [`services_sandbox.rs#L505-L511`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L505-L511): with prefix `src`, an entry `src2/x` passes, and with prefix `src/deep`, any directory whose path is a string prefix of it (such as `s`) passes as an ancestor.
