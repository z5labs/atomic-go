# MaintenanceService

MaintenanceService covers repository repair and consistency checks. `atomic doctor` folds into Repair (the mutating actions) and CheckRepository (the read-only check). ReindexWorkspace is the explicit file-index mutation that used to be hidden in Status [`maintenance_messages.proto#L1-L7`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/maintenance/maintenance_messages.proto#L1-L7). CompactDatabase is physical maintenance of the database file [`maintenance_service.proto#L13-L14`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/maintenance/maintenance_service.proto#L13-L14). The service definition is marked DRAFT, add-only [`maintenance_service.proto#L1-L3`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/maintenance/maintenance_service.proto#L1-L3).

`MaintenanceImpl` implements CompactDatabase, Repair and CheckRepository. ReindexWorkspace returns `UNIMPLEMENTED` [`services_maintenance.rs#L45-L58`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance.rs#L45-L58) [`services_maintenance.rs#L242-L249`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance.rs#L242-L249). The module documentation describes the locking split: CheckRepository opens read-only without the per-repository gate, Repair uses the gate, and compaction additionally needs exclusive access to the database file [`services_maintenance.rs#L1-L10`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance.rs#L1-L10).

METHOD_MATRIX lists Repair, CompactDatabase and CheckRepository [`services.rs#L110-L112`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L110-L112). GetCapabilities reports CompactDatabase with `EXECUTION_SCOPE_LOCAL`, `maintenance.admin`, `CALLER_CLASS_LOCAL` and `RPC_EFFECT_REPOSITORY_WRITE` [`services.rs#L149-L157`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L149-L157). For Repair and CheckRepository it reports `EXECUTION_SCOPE_BOTH` with empty capability, caller and effect lists, which differs from their proto options [`services.rs#L204-L212`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L204-L212). LocalService routes no MaintenanceService method and answers `UNIMPLEMENTED` [`local.rs#L358-L360`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L358-L360).

**Error shape.** Repair and CheckRepository build refusals with `domain_status` (message prefix `atomic:<CODE_NAME>: `, no attached `ErrorInfo`) [`state.rs#L447-L452`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L447-L452); see [how handlers produce errors](../errors.md#how-handlers-produce-errors). Once CompactDatabase has validated its `request_id`, it attaches an encoded [ErrorInfo](../errors.md#errorinfo) carrying that `request_id` as the status details of every error it returns [`compact.rs#L45-L47`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact.rs#L45-L47) [`compact.rs#L189-L204`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact.rs#L189-L204).

## Methods

### CompactDatabase

`rpc CompactDatabase(CompactDatabaseRequest) returns (CompactDatabaseResponse)`, unary [`maintenance_service.proto#L15-L20`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/maintenance/maintenance_service.proto#L15-L20).

Compacts an existing `atomic.redb` in place. When handles are busy, the call waits a bounded time and then fails `UNAVAILABLE`; it is not logical garbage collection [`maintenance_service.proto#L13-L14`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/maintenance/maintenance_service.proto#L13-L14). The handler resolves the canonical database path without opening a Repository and takes the canonical repository's gate with a bounded wait. It then checks the schema version and required capabilities, runs redb's compaction, and reports file sizes before compaction and after closing [`compact.rs#L50-L112`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact.rs#L50-L112) [`compact.rs#L163-L187`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact.rs#L163-L187).

**Behaviour**

- The serving transport is expected to enforce `CALLER_CLASS_LOCAL` and `maintenance.admin` before this handler runs. The handler itself refuses requests carrying sandbox or bearer credentials [`compact.rs#L22-L33`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact.rs#L22-L33) [`CONTRACT.md#L83-L87`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L83-L87).
- Not replayed. A repeated request may run again and report different byte counts, including zero reclaimed bytes [`CONTRACT.md#L75-L81`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L75-L81); `replayed` is always false [`compact.rs#L107`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact.rs#L107).
- The wait budget is `database_wait()` from atomic-agent [`services_maintenance.rs#L51-L55`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance.rs#L51-L55). CONTRACT.md says the gate and file-lock wait is bounded by `ATOMIC_DB_LOCK_WAIT_MS` [`CONTRACT.md#L89-L90`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L89-L90). Gate wait and file-lock retries share one budget measured from the start of the call [`compact.rs#L83-L86`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact.rs#L83-L86) [`compact.rs#L134-L141`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact.rs#L134-L141).
- The handler resolves a sandbox working directory to the canonical `.atomic` and registers the canonical root, so a sandbox and its repository share one gate and one database [`compact.rs#L61-L82`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact.rs#L61-L82) [`tests.rs#L185-L221`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact/tests.rs#L185-L221).
- Cancellation: the gate guard moves into the blocking task, so once compaction starts it finishes even if the caller disconnects [`compact.rs#L92-L96`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact.rs#L92-L96) [`tests.rs#L139-L166`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact/tests.rs#L139-L166) [`CONTRACT.md#L92-L94`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L92-L94).
- Before opening the file writable, the handler opens the repository read-only without migration, takes the maintenance lock and checks again [`compact.rs#L153-L161`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact.rs#L153-L161). A missing database is never created [`tests.rs#L293-L299`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact/tests.rs#L293-L299).
- Persistent savepoints are preserved and reported as a precondition failure [`CONTRACT.md#L95`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L95) [`tests.rs#L345-L371`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact/tests.rs#L345-L371).
- Read paths that do not take the gate, such as CheckRepository, may fail or wait while compaction holds the file [`CONTRACT.md#L90-L92`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L90-L92).
