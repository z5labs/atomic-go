# AttestationService

AttestationService covers the external-signing flow and attestation records: `atomic intent attest --prepare/--signed`, the direct attest verbs (`intent attest`, `memory attest`), verification (`intent verify`, `memory verify`), graph-level attestations (`agent attest`) and change signatures [`attestation_messages.proto#L1-L11`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/attestation/attestation_messages.proto#L1-L11). The external flow is remote-capable by design: a signer holding the key elsewhere needs only the public key [`attestation_messages.proto#L6-L8`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/attestation/attestation_messages.proto#L6-L8). Prepare and record are two calls, and recording verifies the signature against the target as it is at record time, not as it was at prepare time [`attestation_messages.proto#L13-L15`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/attestation/attestation_messages.proto#L13-L15). Both proto files are marked DRAFT, add-only [`attestation_service.proto#L1-L3`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/attestation/attestation_service.proto#L1-L3) [`attestation_messages.proto#L4`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/attestation/attestation_messages.proto#L4).

The proto states that all targets resolve within the named view's effective perspective, that vault attestations are view-local versions, that a sandbox signer must match the grant's acting identity with no daemon default-key fallback, and that signature verification is not authorization [`attestation_messages.proto#L21-L25`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/attestation/attestation_messages.proto#L21-L25). The handlers at this commit implement a narrower surface:

### Conventions on this page

- Every handler resolves the `RepositoryRef` through the daemon registry, which accepts only the `local` authority and fails unknown IDs with `REPOSITORY_NOT_FOUND` [`state.rs#L329-L348`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L329-L348). Those failures, and domain failures mapped through `repository_error`, are described in [how handlers produce errors](../errors.md#how-handlers-produce-errors) and are not repeated per method.
- In the error tables, the ErrorCode column is the [ErrorCode](../errors.md#errorcode) name that `domain_status` writes as an `atomic:<CODE>:` message prefix [`state.rs#L447-L452`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L447-L452). "—" marks a plain tonic status that carries no such prefix.
- **Identities are names in the daemon's identity store.** PrepareAttestation and RecordAttestation pass `identity_did` to `IdentityStore::load_by_name` on the store returned by `IdentityStore::open_default()`, the daemon process's own store [`services_agent.rs#L2984-L2990`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L2984-L2990) [`services_agent.rs#L3010-L3021`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L3010-L3021). VerifyAttestation opens the existing store only, and never loads a private key [`services_agent.rs#L3024-L3049`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L3024-L3049).
- Every handler holds the repository's serialization gate for the whole request [`services_agent.rs#L3112-L3113`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L3112-L3113) [`services_agent.rs#L3167-L3168`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L3167-L3168) [`services_agent.rs#L3431-L3432`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L3431-L3432) [`services_agent.rs#L3570-L3571`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L3570-L3571); the registry comment describes this as full serialization for this slice [`state.rs#L35-L40`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L35-L40).
- These handlers do not run transport authentication or authorization; libatomic does not contain the transport [`lib.rs#L22-L24`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/lib.rs#L22-L24). See [authentication and authorization](../transport.md#authentication-and-authorization) and [version negotiation](../transport.md#version-negotiation).

## Methods

### PrepareAttestation

`rpc PrepareAttestation(PrepareAttestationRequest) returns (PrepareAttestationResponse)`, unary [`attestation_service.proto#L13-L24`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/attestation/attestation_service.proto#L13-L24).

The `--prepare` step: returns the canonical document and the exact signing bytes, using no private key; the proto classes it as a read, with the record and the write happening at RecordAttestation [`attestation_service.proto#L13-L16`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/attestation/attestation_service.proto#L13-L16). For an intent target the handler loads the intent from the vault, lifts it to its canonical node, refuses violations that signing cannot fill, and computes the prepared document and signing bytes for the named identity's public key [`services_agent.rs#L3117-L3139`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L3117-L3139).

**Behaviour**

- The handler makes no write calls [`services_agent.rs#L3117-L3139`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L3117-L3139). A client signs `signing_bytes` with the key held elsewhere and sends the signature to [RecordAttestation](#recordattestation) with the same `identity_did`. RecordAttestation recomputes the signing bytes from the intent as it is then, so a signature over an intent that changed in between fails with `PRECONDITION_FAILED` and the client must prepare again [`services_agent.rs#L3198-L3224`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L3198-L3224).
- The handler opens the repository with `repository()`, not `repository_readonly()` [`services_agent.rs#L3118`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L3118) [`state.rs#L95-L110`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L95-L110).

### RecordAttestation

**Behaviour**

- Not idempotent: the handler echoes `meta` but never replays, so a retry signs, writes and stores again [`services_agent.rs#L1233-L1239`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L1233-L1239) [`services_agent.rs#L3262-L3286`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L3262-L3286).
- The sidecar is written with `std::fs` before the vault store, so a failing vault store leaves the sidecar file behind [`services_agent.rs#L3262-L3267`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L3262-L3267) [`services_agent.rs#L3278-L3284`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L3278-L3284).
- `AttestationInfo.sidecar_path` is the server's filesystem path of the sidecar [`services_agent.rs#L3252-L3257`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L3252-L3257) [`services_agent.rs#L3300`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L3300).
- The vault store and materialize calls take no view [`services_agent.rs#L3278-L3286`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L3278-L3286), so the attestation is not stored as a view-local version as the proto and CONTRACT.md require [`attestation_messages.proto#L23-L24`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/attestation/attestation_messages.proto#L23-L24) [`CONTRACT.md#L208-L211`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L208-L211).
