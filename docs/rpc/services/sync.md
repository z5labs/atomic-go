# SyncService

SyncService covers remote synchronization (`atomic push`, `atomic pull`) and the remote registry, which is persisted in the repository database [`sync_messages.proto#L1-L16`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/sync/sync_messages.proto#L1-L16). The service definition is marked DRAFT, add-only [`sync_service.proto#L1-L3`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/sync/sync_service.proto#L1-L3). Every rpc declares `EXECUTION_SCOPE_LOCAL` and `CALLER_CLASS_LOCAL` [`sync_service.proto#L12-L60`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/sync/sync_service.proto#L12-L60).

`SyncImpl` implements ListRemotes and ManageRemotes itself and delegates PushChanges, PullChanges and BindRemoteProject to `services_sync_remote.rs` [`services_sync.rs#L32-L46`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync.rs#L32-L46) [`services_sync.rs#L144-L149`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync.rs#L144-L149). BindRemoteProject returns `UNIMPLEMENTED` [`services_sync_remote.rs#L1780-L1789`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L1780-L1789).

| Method | Implemented | In-process `LocalService` | Advertised by GetCapabilities |
|---|---|---|---|
| [PushChanges](#pushchanges) | partial | routed | no |
| [PullChanges](#pullchanges) | partial | routed | no |
| [ListRemotes](#listremotes) | yes | routed | no |
| [ManageRemotes](#manageremotes) | yes | routed | no |
| [BindRemoteProject](#bindremoteproject) | no | not routed | no |

No SyncService method appears in METHOD_MATRIX, the list GetCapabilities advertises [`services.rs#L60-L119`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L60-L119).

**Error shape.** Domain refusals in these handlers come from `domain_status`, which formats the status message as `atomic:<CODE_NAME>: <message>` and does not attach the encoded `ErrorInfo` to the status [`state.rs#L423-L452`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L423-L452). Push and pull network-phase failures use `ERROR_CODE_REMOTE`, which `domain_status` maps to gRPC `INVALID_ARGUMENT` through its default arm [`state.rs#L432-L446`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L432-L446). After the prefix, their message is a JSON object with the keys `stage`, `variant`, `url` and `message` [`services_sync_remote.rs#L51-L66`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L51-L66). See [how handlers produce errors](../errors.md#how-handlers-produce-errors) for the general mapping.

<a id="push-and-pull-credentials"></a>
**Push and pull credentials.** The same handler functions serve two callers, which supply credentials differently.

| | Transport handler (`SyncImpl` called by a gRPC server) | In-process `LocalService::call` |
|---|---|---|

For push only, `check_push_credentials` runs first and refuses before any network access when no usable identity or signing key exists [`local.rs#L397-L399`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L397-L399) [`local_sync_test.rs#L342-L350`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/local_sync_test.rs#L342-L350). |

The proto comment describes the same split: transport callers resolve authentication client-side and supply headers and `remote_url`, while LocalService resolves the configured URL and local credentials and rejects caller-supplied `auth_headers`/`remote_url` [`sync_messages.proto#L32-L39`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/sync/sync_messages.proto#L32-L39). The handler does not require `remote_url` from transport callers: without it, the handler resolves the URL from the repository's registry [`services_sync_remote.rs#L437-L470`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L437-L470). The libatomic README lists the identity resolution order that `atomic_remote::auth` applies (explicit identity, agent environment override, URL userinfo, configured server/agent binding, legacy subdomain inference, default identity) and states that an explicit missing identity never falls back [`README.md#L59-L67`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/README.md?plain=1#L59-L67). That order is implemented outside libatomic (see [Open questions](#open-questions)). CONTRACT.md states the same boundary: minted headers never appear in responses, and transport handlers do not read ambient config, identities, signing keys or delegations [`CONTRACT.md#L119-L135`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L119-L135).

## Methods

### PushChanges

`rpc PushChanges(PushChangesRequest) returns (PushChangesResponse)`, unary [`sync_service.proto#L15-L23`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/sync/sync_service.proto#L15-L23).

Uploads a local view's ancestor chain (view manifests and content-addressed objects) to a remote, for `atomic push [--remote]` [`sync_service.proto#L13-L14`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/sync/sync_service.proto#L13-L14). The handler builds the chain root to leaf [`services_sync_remote.rs#L492-L499`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L492-L499), fetches the remote's ref advertisement for those view names [`services_sync_remote.rs#L508-L526`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L508-L526) and plans each view [`services_sync_remote.rs#L528-L618`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L528-L618). Unless the plan reports a conflict or `dry_run` is set, it sends one pack of change files, view snapshots with compare-and-swap ref moves, attestations, provenance graphs and tags, then re-reads the advertisement to verify the result [`services_sync_remote.rs#L650-L903`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L650-L903).

**Behaviour**

- The handler holds the repository's exclusive gate for the whole call, including network I/O [`services_sync_remote.rs#L433-L434`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L433-L434) [`state.rs#L54-L58`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L54-L58).
- Planning compares each local manifest with the remote one. A view absent on the remote stores its whole log and is declared. A differing scope or parent is a conflict. Otherwise the handler stores the local changes absent from the remote, and declares the view when the local change set is not a subset of the remote set [`services_sync_remote.rs#L303-L344`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L303-L344). The planner only produces scope or parent mismatches; the `Diverged` variant is never constructed [`services_sync_remote.rs#L261-L273`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L261-L273) [`services_sync_remote.rs#L315-L329`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L315-L329).
- A dry run still constructs the remote client and fetches the advertisement before it returns the plan [`services_sync_remote.rs#L501-L526`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L501-L526) [`services_sync_remote.rs#L629-L648`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L629-L648).
- Each declared view gets a newly minted snapshot and a ref record whose `expect_old` is the target the remote advertised, so the remote can refuse a concurrent move [`services_sync_remote.rs#L699-L715`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L699-L715).
- Attestations and provenance graphs attached to stored changes are uploaded only when every change they cover is in the union of the chain's logs [`services_sync_remote.rs#L663-L668`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L663-L668) [`services_sync_remote.rs#L722-L795`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L722-L795). Every tag of the local leaf view is added to the pack [`services_sync_remote.rs#L796-L814`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L796-L814).
- When the pack is empty, nothing is sent and no identity bind runs [`services_sync_remote.rs#L842`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L842). Otherwise, if the repository has a project identity, the handler binds it to the remote before upload [`services_sync_remote.rs#L843-L863`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L843-L863); an unbound remote adopts it and a remote bound to a different identity refuses [`identity_transport.rs#L14-L16`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/identity_transport.rs#L14-L16).
- Idempotency: `RequestMeta` is only echoed with `replayed` false [`services_agent.rs#L1233-L1239`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L1233-L1239); this handler consults no replay ledger. Planning skips changes the remote already advertises [`services_sync_remote.rs#L580-L586`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L580-L586), so repeating a push whose changes are already on the remote stores no changes; a test repeats a push and observes no second upload [`local_sync_test.rs#L370-L376`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/tests/local_sync_test.rs#L370-L376). A repeat skips the upload only when the leaf view has no tags. Every push adds each tag of the local leaf view to the pack [`services_sync_remote.rs#L796-L814`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L796-L814), and the identity bind, the upload and the verify re-read run whenever the pack is not empty [`services_sync_remote.rs#L842-L902`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L842-L902), so a repeat push from a view with a tag binds, uploads and re-reads again.

- A failed change save or view reconciliation is reported, not raised. A change that fails to save is counted in `changes_failed` with `ok` false. A view that fails to reconcile adds an `apply_errors` entry. Sidecar, identity, vault and tag problems become `warnings` [`services_sync_remote.rs#L1402-L1412`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L1402-L1412) [`services_sync_remote.rs#L1532-L1535`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L1532-L1535) [`services_sync_remote.rs#L1026-L1095`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L1026-L1095). The README tells callers to inspect pull partial-failure reports instead of treating them as success [`README.md#L79-L81`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/README.md?plain=1#L79-L81). The call can still fail as a whole, with no `PullReport`, after it has saved changes [`services_sync_remote.rs#L1360-L1436`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L1360-L1436) and reconciled views [`services_sync_remote.rs#L1515-L1547`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L1515-L1547): a change missing from the pack stops the save loop after the changes before it were saved [`services_sync_remote.rs#L1415-L1423`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L1415-L1423), and after reconciliation the sidecar import, signer-key discovery, set-id verification, workspace entry and tag step can each return an error [`services_sync_remote.rs#L1556`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L1556) [`services_sync_remote.rs#L1580-L1585`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L1580-L1585) [`services_sync_remote.rs#L1602`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L1602) [`services_sync_remote.rs#L1639-L1640`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L1639-L1640) [`services_sync_remote.rs#L1698`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L1698).
