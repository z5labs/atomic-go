# KnowledgeService

KnowledgeService serves knowledge-graph reads and maintenance. `QueryGraph` carries every interactive read (content/code search, KG search, entity, neighbors, callers, graph slice, plan execution, RAG ask) and `MaintainKnowledgeGraph` carries the embed/enrich/reindex side [`knowledge_messages.proto#L4-L7`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/knowledge/knowledge_messages.proto#L4-L7). `GetProjectIdentity` and `GetWorkflowSnapshot` are read-only, repository-wide workflow inspection for `repo identity show` and client-side SHACL validation [`knowledge_messages.proto#L8-L9`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/knowledge/knowledge_messages.proto#L8-L9). Local file-index construction (`query index`) stays client-side, and `QueryGraph`'s view-scoped search/callers/content paths must project recorded graph bytes without building or refreshing a persistent index [`knowledge_messages.proto#L10-L12`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/knowledge/knowledge_messages.proto#L10-L12). Both proto files are marked DRAFT, add-only [`knowledge_service.proto#L1-L3`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/knowledge/knowledge_service.proto#L1-L3).

All four methods have handlers in `KnowledgeImpl` [`services_agent.rs#L3779`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L3779) [`services_agent.rs#L3827`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L3827) [`services_agent.rs#L3873`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L3873) [`services_agent.rs#L4331`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L4331). `QueryGraph` is partial: every query verb has a handler branch, but several request fields are ignored and some response fields are never populated as the contract describes (see each verb). Only `QueryGraph` and `GetWorkflowSnapshot` are routed through the in-process `LocalService` [`local.rs#L328-L347`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L328-L347); `MaintainKnowledgeGraph` is the only one absent from `METHOD_MATRIX` [`services.rs#L94-L96`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L94-L96).

### Conventions on this page

- Every handler resolves the `RepositoryRef` through the daemon registry, which accepts only the `local` authority and fails unknown IDs with `REPOSITORY_NOT_FOUND` [`state.rs#L329-L348`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L329-L348). Those failures, and domain failures mapped through `repository_error`, are described in [how handlers produce errors](../errors.md#how-handlers-produce-errors) and are not repeated per method.
- Every handler runs its work in a blocking task, and returns a plain `INTERNAL` status with no `atomic:` prefix when that task cannot be joined: GetProjectIdentity [`services_agent.rs#L3822-L3823`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L3822-L3823), GetWorkflowSnapshot [`services_agent.rs#L3868-L3869`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L3868-L3869), QueryGraph [`services_agent.rs#L4326-L4327`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L4326-L4327) and MaintainKnowledgeGraph [`services_agent.rs#L4468-L4469`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_agent.rs#L4468-L4469). The per-method error tables do not repeat this row.
- In the error tables, the ErrorCode column is the [ErrorCode](../errors.md#errorcode) name that `domain_status` writes as an `atomic:<CODE>:` message prefix [`state.rs#L447-L452`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L447-L452). "—" marks a plain tonic status that carries no such prefix.
- Every handler holds the repository's serialization gate for the whole request; the registry comment describes this as full serialization of repository access for this slice [`state.rs#L35-L40`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L35-L40). A slow `QueryGraph` (for example `rag_ask`, which runs an LLM loop) therefore delays every other request on the same repository.
- These handlers do not run transport authentication or authorization; libatomic does not contain the transport [`lib.rs#L22-L24`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/lib.rs#L22-L24). See [authentication and authorization](../transport.md#authentication-and-authorization) and [version negotiation](../transport.md#version-negotiation).
