# Errors

The contract's error model has two channels. Failures travel as a gRPC status, with an `ErrorInfo` message as the machine-readable detail. Domain refusals that must carry a recovery payload, such as a stale-view skeleton, travel inside the response message as a `oneof` outcome instead ([`error.proto#L15-L19`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/common/error.proto#L15-L19); [`README.md#L104-L106`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/README.md?plain=1#L104-L106)).

At this commit libatomic implements the first channel differently from the contract: handlers put the error code in the status message text, and do not attach `ErrorInfo`, except in one method. This page describes what a client actually receives, then the code vocabulary, then the mappings the handlers use.

## On the wire

A failed call returns a gRPC status: a status code and a message string. libatomic's handlers return tonic `Status` values as their error type ([`mod.rs#L35-L39`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/mod.rs#L35-L39)). The transport shell that serves them is not part of libatomic ([`lib.rs#L22-L24`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/lib.rs#L22-L24)), so libatomic does not show whether that shell rewrites statuses; see [Open questions](#open-questions).

A client can receive four shapes:

1. **A domain status (most handler errors).** `domain_status` sets the gRPC code from the [mapping below](#how-handlers-produce-errors) and sets the message to `atomic:<NAME>: <message>`, where `<NAME>` is the [ErrorCode](#errorcode) name without its `ERROR_CODE_` prefix ([`state.rs#L449-L452`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L449-L452), [`state.rs#L391-L422`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L391-L422)). For example, an unregistered repository produces gRPC `NOT_FOUND` with the message `atomic:REPOSITORY_NOT_FOUND: repository is not registered with this daemon; resolve it by path first` ([`state.rs#L342-L347`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L342-L347), [`state.rs#L433`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L433)). The function builds and encodes an `ErrorInfo` but discards it; a code comment says rich `grpc-status-details-bin` attachments are planned and that "the stable code rides the message prefix until then" ([`state.rs#L423-L431`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L423-L431), [`state.rs#L447-L448`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L447-L448)). The only exception is `ERROR_CODE_UNSPECIFIED`, whose prefix name keeps the full `ERROR_CODE_UNSPECIFIED` spelling ([`state.rs#L393`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L393)); no handler produces it.
2. **A status with an `ErrorInfo` detail (`MaintenanceService.CompactDatabase` only).** After its credential and request-ID checks, that handler wraps every failure of the compaction itself with `with_request_id`, which keeps the gRPC code and message and attaches the protobuf encoding of an `ErrorInfo` (code, message, echoed `request_id`) as the status details ([`compact.rs#L45-L47`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact.rs#L45-L47), [`compact.rs#L189-L204`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact.rs#L189-L204)). Its test decodes the details directly as `ErrorInfo` ([`tests.rs#L24-L31`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact/tests.rs#L24-L31)). The details are a bare `atomic.ErrorInfo`, not wrapped in another message. See [CompactDatabase](services/maintenance.md#compactdatabase).
3. **A plain status.** Some paths build a tonic status directly, with no `atomic:` prefix and no detail. Examples: background-task join failures map to `INTERNAL` ([`services_sandbox.rs#L56-L58`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L56-L58)); the compaction guard returns `PERMISSION_DENIED` when a token or `authorization` header is present ([`compact.rs#L25-L33`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact.rs#L25-L33)); the in-process `LocalService` returns `INVALID_ARGUMENT` for an undecodable request and `UNIMPLEMENTED` for an unrouted method ([`local.rs#L442-L444`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L442-L444), [`local.rs#L358-L360`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/local.rs#L358-L360)).

4. **A domain status with trailing metadata (`RepositoryMutationService.Record` only).** When the recorder refuses a file as too large, the `ERROR_CODE_CHANGE_REJECTED` status (gRPC `FAILED_PRECONDITION`) also carries the metadata entries `atomic-record-error: file-too-large`, `atomic-file-path-bin` (the path's raw bytes, binary metadata), `atomic-file-size` and `atomic-file-limit` (decimal text) ([`services.rs#L1593-L1613`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1593-L1613)). No other handler sets status metadata. See [Record](services/repository-mutation.md#record).

A client should therefore read the gRPC code first, then take the `ErrorCode` from the details when they decode as `ErrorInfo`, else from an `atomic:<NAME>: ` message prefix, else treat the code as unknown. Contract tests are meant to assert on code and context keys, never on message prose ([`error.proto#L74-L77`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/common/error.proto#L74-L77)).

Some messages carry structured text after the prefix. Sync failures put a JSON object with `stage`, `variant`, `url` and `message` keys in the message, under `ERROR_CODE_REMOTE` ([`services_sync_remote.rs#L51-L66`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sync_remote.rs#L51-L66)). Workspace reconciliation refusals include remediation commands in the message ([`state.rs#L153-L158`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L153-L158)).

## Error vocabulary

### ErrorCode

The stable error vocabulary. Values 28 to 999 are reserved, and numbers are never reused ([`error.proto#L3`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/common/error.proto#L3), [`error.proto#L71`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/common/error.proto#L71)). "gRPC status" is the code `domain_status` sends with that value ([`state.rs#L432-L446`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L432-L446)). "Produced" says whether any libatomic code creates the value at this commit, from a search of `libatomic/src`, with one example.

### repository_error

`repository_error` maps any `atomic_repository::RepositoryError` to `ERROR_CODE_REPOSITORY` with the error's text as the message, for callers that have no more specific mapping ([`state.rs#L455-L459`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L455-L459)). It therefore arrives as gRPC `INTERNAL` with an `atomic:REPOSITORY: ` prefix. Method pages that list "repository errors" mean this path. Some handlers map selected variants first; for example the sandbox `view_error` turns a missing view into `ERROR_CODE_NOT_FOUND` and passes the rest to `repository_error` ([`services_sandbox.rs#L97-L105`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L97-L105)), and the tag handlers map a duplicate or invalid tag name to `ERROR_CODE_INVALID_ARGUMENT` and a missing view to `ERROR_CODE_VIEW` ([`services_tag.rs#L47-L67`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_tag.rs#L47-L67)).

### Refusals as plain data

Other responses report refusals as plain data rather than as `ErrorInfo`. For example `RemoveFilesResponse.refusals` lists each refused path with a reason such as `uncommitted-edits`, both for previews and for mutations ([`repository_mutation_messages.proto#L63-L65`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/repository_mutation/repository_mutation_messages.proto#L63-L65), [`repository_mutation_messages.proto#L78-L84`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/services/repository_mutation/repository_mutation_messages.proto#L78-L84)); see [RemoveFiles](services/repository-mutation.md#removefiles).

The same code can arrive on either channel. `ERROR_CODE_VIEW_STALE` is a refusal outcome on `SubmitChange` ([`services_sandbox.rs#L818-L827`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L818-L827)) but a gRPC `FAILED_PRECONDITION` error from the Record and InsertChanges fences ([`services.rs#L1215-L1223`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1215-L1223), [`services.rs#L1244-L1255`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services.rs#L1244-L1255)) and from the sandbox `GetFileStates` and `GetChanges` fence ([`services_sandbox.rs#L181-L192`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L181-L192)). [ViewSnapshot](types.md#viewsnapshot) lists the fences.

## Open questions

- **ErrorInfo is not attached to domain errors.** The contract says transport failures carry `ErrorInfo` as the detail payload ([`error.proto#L15-L17`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/common/error.proto#L15-L17)) and that refusals echo the request ID in `ErrorInfo` ([`CONTRACT.md#L54-L55`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L54-L55)). `domain_status` drops it and relies on the message prefix "until" rich attachments land ([`state.rs#L429-L431`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L429-L431), [`state.rs#L447-L448`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L447-L448)). The prefix format may change when that happens; no date or version is given.
- **Detail encoding for CompactDatabase.** The details bytes are a bare `atomic.ErrorInfo` ([`compact.rs#L203`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact.rs#L203)). tonic carries `Status` details in the `grpc-status-details-bin` trailer, where gRPC libraries conventionally expect a `google.rpc.Status`. libatomic does not say how a non-Rust client should decode these bytes, or whether the encoding will change to `google.rpc.Status` with an `ErrorInfo` in its details.
- **Default gRPC mapping.** Many domain codes, including `ERROR_CODE_REMOTE` and the provenance codes, fall through to `INVALID_ARGUMENT` ([`state.rs#L445`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L445)), and `ERROR_CODE_PROTOCOL_VERSION_MISMATCH` maps to `INTERNAL` ([`state.rs#L443`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/state.rs#L443)). libatomic gives no rationale; clients that retry on gRPC codes cannot rely on these.
- **ERROR_CODE_VIEW for a missing view.** The proto describes `ERROR_CODE_VIEW` as "view not visible to caller" ([`error.proto#L52`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/atomic/common/error.proto#L52)), but handlers also use it for a view that does not exist, which arrives as `PERMISSION_DENIED` ([`services_tag.rs#L62-L64`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_tag.rs#L62-L64), [`services_query.rs#L354-L359`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_query.rs#L354-L359)), while other handlers report a missing view as `ERROR_CODE_NOT_FOUND` ([`services_sandbox.rs#L97-L102`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_sandbox.rs#L97-L102)).
- **UNAVAILABLE.** `CONTRACT.md` says a busy database during compaction returns `UNAVAILABLE` ([`CONTRACT.md#L89-L90`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L89-L90)). `domain_status` has no mapping to `UNAVAILABLE`; only the compaction handler returns it ([`compact.rs#L89`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact.rs#L89)), and the `ErrorInfo` attached to it is coded `ERROR_CODE_RESOURCE_EXHAUSTED` ([`compact.rs#L191`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/daemon/services_maintenance/compact.rs#L191)).
- **Errors from the transport shell.** Version-header checks, method allowlists, authentication and message-size limits belong to the serving shell, not libatomic ([`lib.rs#L22-L24`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/src/lib.rs#L22-L24); [`CONTRACT.md#L34-L38`](https://github.com/atomicdotdev/atomic/blob/a6c3e359456e83cf5a967a2e8265f11e0ba45d80/libatomic/proto/CONTRACT.md?plain=1#L34-L38)). Which codes and messages that shell returns is not specified in libatomic.
